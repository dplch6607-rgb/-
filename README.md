# Мастерская электроники: учёт инвентаря, выдач и очереди заявок

Итоговый проект курса «Python и основы CS».
**Автор:** Лазарев Владимир Владимирович, группа ПО-2402.

## Назначение

В учебной мастерской электроники есть два вида имущества: **инструменты и платы** (паяльная станция,
мультиметр, Arduino) — их возвращают, и **расходники** (резисторы, припой, провод) — они заканчиваются.
Программа отвечает на три вопроса:

1. **Что где лежит и у кого?** Склад, поиск, сортировка, журнал выдач и возвратов.
2. **Что скоро закончится?** Отчёт «требует внимания»: расходники ниже минимума, инструменты, которые все выданы.
3. **Кто следующий, если нужного нет?** Справедливая очередь заявок (FIFO отдельно по каждому предмету):
   освободился инструмент или пришло пополнение — ожидающий получает его автоматически.

Данные не пропадают: после каждой правки состояние сохраняется в `data/state.json`, при следующем запуске
работа продолжается с того же места.

## Запуск

Нужен Python 3.9+ и ничего больше (только стандартная библиотека, см. `requirements.txt`).

```bash
python main.py                          # меню; склад пуст → пункт 11 загрузит data/items.csv
python main.py --import data/items.csv  # импортировать каталог и сразу открыть меню
python -m unittest -v                   # тесты (114 шт.)
```

Параметры `main.py`: `--state` (файл состояния), `--report` (куда писать отчёт), `--csv` (каталог для
импорта по умолчанию), `--import CSV` (импорт перед запуском), `--log` (файл журнала, по умолчанию `logs/workshop.log`).

### Команды меню

| № | Команда | Что делает |
|---|---|---|
| 1 | Показать склад | Сортировка по артикулу / названию / категории / остатку, по возрастанию или убыванию |
| 2 | Поиск | По артикулу, по началу названия, по части названия, по категории (экран называет алгоритм и его сложность) |
| 3 | Добавить предмет | Инструмент или расходник; каждое поле проверяется сразу, при ошибке — повторный запрос |
| 4 | Изменить | Название и/или категория (пусто — не менять) |
| 5 | Удалить | С подтверждением; нельзя удалить выданное или то, на что есть заявки |
| 6 | Выдать | Выдаёт сразу, а если нет в нужном количестве — ставит заявку в очередь |
| 7 | Принять возврат | Показывает невозвращённые выдачи; освободившееся сразу отдаётся первому в очереди |
| 8 | Пополнить запас | Увеличивает запас и обслуживает очередь |
| 9 | Выдачи и очередь | Что сейчас на руках и кто в каком порядке ждёт |
| 10 | Отчёт | На экран и в `data/report.json` |
| 11 | Импорт из CSV | Загружает каталог; плохие строки отклоняются с причиной |

Пример реального сеанса — `examples/session_demo.txt`.

## Данные

**Входной CSV** (`data/items.csv`, образец с ошибками — `data/items_with_errors.csv`):

```csv
sku,name,category,kind,quantity,min_stock,unit
SLD-001,Паяльная станция,Пайка,tool,4,,
RES-010,Резистор 10 кОм,Компоненты,consumable,400,100,шт
```

- `sku` — артикул вида `ABC-123` (2–4 латинские буквы, дефис, 3 цифры);
- `kind` — `tool` (возвращаемый; `quantity` = сколько всего) или `consumable` (расходник);
- `min_stock` и `unit` нужны только расходникам (пусто → 0 и «шт»).

**Выходной JSON** — `data/state.json` (состояние) и `data/report.json` (отчёт). Готовые примеры, полученные
реальным прогоном сценария, лежат в `examples/state.json` и `examples/report.json`.

## Как требования курса решают задачи пользователя

| Требование | Где в коде | Какую задачу пользователя решает |
|---|---|---|
| `list` для порядка | `Inventory._items`, журнал выдач | Склад показывается в стабильном порядке и сортируется как угодно |
| `dict` для поиска | `Inventory._by_sku` | Выдача и возврат находят предмет по артикулу мгновенно, при любом размере склада |
| `set` для уникальности | `Inventory._categories`, `blocked` в очереди | Список категорий без повторов; заявки одного предмета не обгоняют друг друга |
| Свой поиск | `algorithms.py`, `Inventory.search`, `Workshop.find_loan` | Найти предмет по началу названия, категории, номеру выдачи |
| Своя сортировка | `merge_sort`, `Inventory.sorted_by` | Просмотр склада по любому полю, вверх и вниз |
| Big-O | таблица ниже, `docs/TRACE.md` | — (обоснование выбора структур) |
| Пустая коллекция, нет записи, повторы | `ItemNotFoundError`, `DuplicateItemError`, тесты `empty_*` | Опечатка в артикуле даёт понятную ошибку, а не падение; дубли из CSV отклоняются |
| ≥4 модуля | `main.py`, `models.py`, `storage.py`, `ui.py` (+`algorithms.py`, `exceptions.py`) | Каждую часть можно менять отдельно |
| ≥3 класса, композиция | `Workshop` ◆ `Inventory` ◆ `Item`; `Workshop` ◆ `Loan`, `LoanRequest` | Единая точка управления: интерфейсу достаточно `Workshop` |
| Защита состояния, `property` | `available ≤ total`, `quantity ≥ 0`, `sku` без setter | Нельзя получить «−5 резисторов» или «выдано больше, чем есть» |
| Полиморфизм | `take`, `give_back`, `needs_attention`, `describe` у двух типов | Отчёт и интерфейс работают с любым предметом одинаково |
| `dataclass` | `Loan`, `LoanRequest` (frozen), `ImportResult` | Выдача и заявка — простые записи без лишнего кода |
| CSV (`csv`) | `storage.read_csv_rows` | Каталог загружается файлом, а не вводом 22 позиций вручную |
| JSON (`json`) | `save_state`, `load_state`, `save_report` | Продолжить работу после перезапуска; отчёт для передачи |
| Поэтапно: чтение → проверка → преобразование → обработка → запись | `import_items` | Ошибка в одной строке не ломает импорт всех остальных |
| Генератор | `read_csv_rows`, `_validate_rows`, `_transform_rows`, `iter_active_loans` | Большой каталог не загружается в память целиком |
| `deque` | `Workshop._waitlist` | Справедливая очередь: `popleft` за O(1), порядок = порядок заявок |
| Проверка ввода и файлов | `ui._ask_*`, `storage._check_row` | Неверный ввод не роняет программу и не портит данные |
| Свои исключения | `exceptions.py` | Понятное сообщение вместо traceback; настоящие баги не скрываются |
| Нет пустого `except` | везде указаны типы | Сбои не замалчиваются |
| `logging` | `logs/workshop.log` | След событий и ошибок: кто что взял, какие строки отклонены |
| Type hints, docstrings | все публичные функции и классы | Код читаем и проверяем |

## Сложность основных операций

| Операция | Реализация | Время | Комментарий |
|---|---|---|---|
| Найти предмет по артикулу | `dict` | O(1) в среднем | перебор списка был бы O(n) |
| Добавить предмет | `list.append` + `dict` + `set.add` | O(1) амортизированно | |
| Удалить предмет | `list.remove` + пересборка `set` | O(n) | редкая операция |
| Сортировка склада | `merge_sort` | O(n log n), память O(n) | устойчивая |
| Поиск по началу названия | сортировка (один раз, кэш) + бинарный поиск | O(n log n) один раз, затем O(log n + k) | предусловие: список отсортирован |
| Поиск по части названия / категории | `linear_find_all` | O(n) | предусловий нет |
| Найти выдачу по номеру | бинарный поиск по `loan_id` | O(log L) | журнал упорядочен по построению |
| Поставить заявку / взять первую | `deque.append` / `popleft` | O(1) | у `list.pop(0)` было бы O(n) |
| Обслужить очередь | один проход по `deque` | O(m), m — число заявок | |
| Построить отчёт | один проход по складу и журналу | O(n + L + m) | |

## Ошибки и журнал

- Пользовательский ввод проверяется сразу и запрашивается заново; ошибки предметной области (`WorkshopError`)
  интерфейс показывает как «Ошибка: …» и продолжает работу.
- Плохие строки CSV отклоняются поодиночке: причина и номер строки попадают на экран (первые 10) и в журнал.
  Если файл ломается посреди импорта — уже добавленное откатывается.
- Повреждённый `state.json`: `main.py` объясняет проблему и завершается с кодом 1, без «тихого» продолжения.
- Запись JSON атомарна: временный файл + `os.replace`.
- Журнал: `logs/workshop.log` (INFO — события, WARNING — отклонённые данные и ошибки команд, ERROR — сбои хранения).

## Ограничения

- Консольное приложение для одного пользователя; одновременная работа нескольких копий не поддерживается
  (состояние — один JSON-файл).
- Возврат принимается только целиком (частичный возврат по одной выдаче не предусмотрен).
- Нет сроков возврата и учёта просрочек.
- Расходники при выдаче списываются безвозвратно; отмена выдачи расходника не предусмотрена.
- Состояние хранится целиком в одном JSON и читается целиком (в отличие от CSV-импорта, который идёт построчно);
  для склада в сотни и тысячи позиций это не проблема.
- Название и категория меняются через пункт 4, артикул изменить нельзя (нужно удалить и создать заново).
